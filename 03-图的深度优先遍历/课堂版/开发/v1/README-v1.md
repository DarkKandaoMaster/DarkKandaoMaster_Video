# 图的深度优先遍历：课堂版

2026-11-16 做。任课老师 2026-11-24 上课用，**只做正课**（DFS 算法本身）。内容来自同目录的 B 站视频工程（`..\`，图、序列、邻接表、非连通图都是同一份数据，没有改动视频工程的任何文件）。

老师自己讲，页面不配音。全部手动、一按一步，没有自动播放。单文件、完全离线（不联网、不用 CDN 和网络字体，build 时检查过里面没有任何网址），1920×1080 设计，任意窗口等比缩放。**画面底部没有按键提示条**，也没有按钮，按键只写在这份 README 里；右下角只有一行很淡的 20px 小字"段 · 本段第几步"（如 `3 · 5/16`），给老师自己看进度。

### 3 走一遍（16 步：每进一个顶点或退一步算一步）

规则：先挑编号小的（和教材一样，也和按教材邻接表走的结果一样）。每一步的字（核对脚本逐字对过）：

| 步 | 标题 | 下面几行 |
|---|---|---|
| 1 | 从 v1 出发 | visited[v1] = T，v1 进栈；还没来过的：v2、v3 → 下一个去哪？（规则：先挑编号小的） |
| 2 | 走到 v2 | visited[v2] = T，v2 进栈；v1 来过了，跳过；还没来过的：v4、v5 → 下一个去哪？ |
| 3 | 走到 v4 | visited[v4] = T，v4 进栈；v2 来过了，跳过；还没来过的：v8 → 下一个去哪？ |

| 6 | 退回 v8 | v5 出栈，栈顶又是 v8；v8 的邻接点也都来过了 → 继续退 |

老师可以说：
- 每个"下一个去哪？"都是**互动点**，可以让学生先说再按（前几步问，后面熟了就直接按）。
- 第 5、12 步"撞南墙！怎么办？"：**问学生**"该退到哪？"——答案就是栈顶下面那个。
- 第 6–9 步连续退栈："退的时候不访问，只是回到上一层，看看那一层还有没有别的路。"
- 嫌慢可以随时按 Enter 直接看结束那一步。

### 5 邻接表（3 步）

左边是缩小的图，中间是教材式邻接表（顶点表 + 边链表，adjvex | nextarc，下标从 0 起，`∧` 表示空指针），右边是访问序列。

| 步 | 画面 | 老师可以说的 |
|---|---|---|
| 1 | "考试怎么考？**给定存储结构：邻接表**；每个顶点挂一条链，链里存邻接点的下标（从 0 起）；按这张表从 v1 出发：第一步去哪？"序列区多一行"③ 按邻接表走"（**互动点**） | "下标 1 就是 v2。v1 的链第一个是 1，所以第一步去哪？" |
| 2 | "沿着链从前往后找，**第一个没来过的就去**；走出来和第 ① 条一样（链本来就是从小到大）"。表里一格一格扫：要去的格变绿，已经来过的格打斜杠，图上绿色走一遍，第 ③ 行 = ① | "FirstAdjVex 就是链的第一个，NextAdjVex 就是往后挪一格。" |
| 3 | "链的顺序一变，序列就变：**链倒过来 → 第 ② 条**；表一给定，每一步都定死了 → **序列唯一**（考研常考：按给定的邻接表写 DFS 序列）"。所有链倒序，③ 变成和 ② 一样 | "同一张图，存法不同，DFS 序列就不同；但存法一定，答案就唯一。" |

## 3D 用在哪、为什么

只用了两处，都是"立体比平面更能说明道理"的地方；数字和文字全部在平面的 HUD 层（2D 画布），3D 层只画东西不画字（顶点名字也是 HUD 按 3D 坐标投影后画的，所以和 2D 模式一样清楚）。

1. **第 1 段迷宫（5 步）**：口诀"一条路走到黑，撞了南墙再回头"本来就是空间里的事。立体的墙挡住视线，小人只能看到眼前的岔路，正好对应 DFS"只看当前顶点的邻接点"；插旗 = visited；红栅栏 = 撞南墙。最后一步墙降下去、压平成第 3 段那张平面图——3D 镜头的最终位置是正俯视，一个 3D 单位正好 = 画面 100 像素，所以压平后的图和第 3 段的 2D 图**严丝合缝**，切换时不跳。
2. **第 9 段第 2 步"把生成树提起来"**：把 v1 往上一提，树按深度一层层垂下来，"深度"变成看得见的高度，直接对上右边"栈最深时"的那根栈。这是 DFS 名字里"深度"的直观意思，平面图上不容易看出来。

2D 兜底：第 1 段画成俯视的平面迷宫（同样的房间、旗子、问号、红栅栏、小人），第 9 段第 2 步画成侧视的分层树（同样的层号和栈）。两种模式的步数、每一步的字和状态由 verify.py 逐步比过，完全相同。

性能：本机（RTX 4060 笔记本）3D 满帧。墙用 InstancedMesh 一次画完，3D 只在这 6 步里渲染，其他步骤 WebGL 画布隐藏、不耗显卡。

## 对讲法的调整和理由

1. **先迷宫后图**：用迷宫把口诀和"插旗 / 原路退回"两个动作讲直观，第 2 段再把这两个动作对应成 visited 数组和栈，第 3 段才在图上走。学生先有画面，再看数据结构。
2. **第 3 段"一进一退各一步"**：每访问一个顶点一步、每退一步一步（共 16 步），中间"来过了，跳过"的检查合并进同一步写成一行。这样每步屏幕上只变一件事，栈的变化看得清；连续退栈（v5 → v8 → v4 → v2 → v1）故意不合并，让学生看到"退的时候不访问"。
3. **每个访问步都写"还没来过的：… → 下一个去哪？"**，把选择题摆在屏幕上，老师随时可以问；第 1 步写明规则"先挑编号小的"。
4. **最后一次退栈写"v1 也出栈"**（不是"继续退"），因为栈里只剩 v1 了，再退就是栈空、遍历结束。
5. **第 4 段先挑编号大的再走一遍**，用两条都对的序列引出"不唯一"，并给出"从 v1 出发一共 8 种"（Python 把 7! 种挑法逐个模拟数出来的）。
6. **第 5 段用教材式邻接表**（adjvex 下标从 0 起，v1 对应 0），讲清考题为什么有唯一答案；链倒过来正好变成第 ② 条，和第 4 段呼应。
7. **第 6 段非连通图**用 B 站视频那张 G6，引出 DFSTraverse 外层循环和"调用次数 = 连通分量个数"。
8. **第 7 段代码按教材算法 7.4、7.5**，只去掉了 `Status (*Visit)(int v)` 这个函数指针参数（课堂上不讲函数指针），三行注释把代码和前面讲的三件事连起来。
9. **小练默认起点 v6**：答案不是"直觉上的近处优先"（v7 就在 v6 旁边却最后一个），栈最深 7 层，能看出 DFS"深"的特点；也可以现场点顶点换题。
10. **结尾加生成树和"提起来"**：把"深度"和"栈深"连起来，顺便给下节课 BFS 的生成树对比留个铺垫。
11. 小结最后一行写"下节课：广度优先遍历（BFS）"。

## 已知限制 / 需要老师或用户定的

- **算法编号**：我按严蔚敏、吴伟民《数据结构（C 语言版）》（清华）写的"算法 7.4、7.5"，没有书可查；如果老师用的是别的版本（比如人民邮电第 2 版），请核一下编号，改 `开发\src\dfs.template.html` 里第 7 段标题那一行再 build。
