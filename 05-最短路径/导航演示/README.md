# 导航演示：从"手机导航"讲到迪杰斯特拉

课堂上用的引入环节（2026-11-10 做）。用湖州师范学院校园地图：先问"从生命科学学院到 32 号教学楼怎么走最近"，给出一张导航风格的地图和蓝色路线，再把地图放倒、路口变顶点、路段变边，用迪杰斯特拉一步步算，最后揭晓**算出来的最短路径就是导航给的那条蓝线**。

老师自己讲，页面不配音。单文件、完全离线（图片 base64 内嵌，不联网、不用网络字体），1920×1080 设计，任意窗口等比缩放。

## 怎么用（四步）

| 步 | 画面 | 怎么操作 |
|---|---|---|
| 1 导入 | 手绘校园地图（右上角注明出处），起点、终点画圈，大字"从生命科学学院到 32 号教学楼，怎么走最近？" → 按一下淡入导航风格地图：起终点图钉、蓝色路线、顶部卡片"全程 280 米 · 步行约 4 分钟" | 想换起终点：直接**点地图上的楼名**（默认改终点；点左下角"终点 / 起点"按钮或按 S 切换成改起点），路线和卡片马上变，后面几步都跟着换；R 恢复默认 |
| 2 变成图 | 地图向后放倒、变淡；路口变成圆圈顶点（起点、终点写楼名，其余用字母），再按一下路段变成边，标上长度（米） | |
| 3 迪杰斯特拉 | 左边是图，右边是大表格（顶点 / dist / path）。先显示初始化；**前 3 下一按一步**：锁定 dist 最小的顶点，被更新的邻居数字跳一下，被改小的旧值划掉；**第 4 下开始自动播放**（每 1.1 秒锁一个），再按一下暂停、再按继续；终点被锁定就停 | 暂停时右键 / ← 可以一步步往回退 |
| 4 揭晓 | 最短路径亮起橙色，和第 1 步的蓝线重合；大字"导航给你的路线 = 最短路径"，下面"全程 280 米 = dist[32号楼] = 280" | 终点锁定后自动进入 |

## 为什么选 生命科学学院 → 32 号教学楼

情景："上完生科院的课，赶去 32 号楼上下一节"。

- **两栋楼都常去**：32 号是公共教学楼，生科院在德清湖西南。
- **有两条长度接近的走法，最短的不显然**：
  - 看起来最顺的：沿梁希路往北到明达路，再沿明达路往西 —— 120 + 180 = **300 米**（实测 304.7 米）；
  - 实际更短的：沿工学院南侧路往西，绕到图书馆东北角，再沿郑凝路往北 —— 130 + 70 + 80 = **280 米**（实测 280.0 米）。
  - 差 20 米（约 7%），光看地图不好判断，正好用算法来定。
- **算法里有一次"先找到较长的，后被改成更短的"**：第 1 次锁定 F 后，32 号楼先拿到 300（经 F）；第 3 次锁定 B 时改成 280（经 B），旧值 300 被划掉。这一下正好落在"前 3 下一按一步"里，老师可以停下来讲。
- 最短路唯一（第二短 300 米）；结束时各顶点 dist 互不相同，锁定顺序没有同距离的歧义；锁定 5 次就到终点（≤ 10）。
- 北门 E 会被锁定（250 < 280），说明算法会先把"更近的点"都看一遍；和润楼 H（330）、明达楼 A（370）算出来了但没锁，说明终点锁定就可以停。

候选里也试过 和润楼 → 数字图书馆 等几对，要么没有"改小"、要么改小要到自动播放阶段才出现，所以定了这一对。德清湖东侧的湖边步道（经安吉园）也量了，但明显更远，放进图里只会让"改小"推迟到自动播放，所以没放。

**微调（只有这两条，都在 10% 以内）**：

| 边 | 实测 | 四舍五入应为 | 显示 | 偏差 | 为什么 |
|---|---|---|---|---|---|
| F–G 梁希路南段 | 128.1 | 130 | 120 | −6.3% | 取 130 时 F 和 D 离起点都是 130，第 1 次锁定就同距离、挑谁都对，初学者会卡住；6 栋楼里有 12 个有序对出现这种锁定平局。OSM 沿路折线直接量这一段是 125.7 米，120 和它差 −4.5% |

## 距离怎么量的

1. **路网走向**：按 `地图\体育场地分布图.jpg`（2023 年版，道路画得最清楚）描路口和道路折线。
2. **比例尺**：`地图\总平面图.jpg`（1:2000）右下角比例尺刻度 0 / 10 / 50 / 100 / 200 米，线性拟合得 **1 米 = 3.8787 像素**（100 米 = 387.9 像素）。
3. **对齐**：在两张图上各取 9 个地标（数字图书馆、和润楼、会堂、32 号楼、鹊望亭、安吉园圆形广场、明达路×梁希路、明达路×郑凝路、北门），最小二乘拟合仿射变换（体育场地分布图 → 总平面图），RMS 残差 7.4 米（单点 1.1 – 13.3 米）。把每条道路折线变换到总平面图上，按比例尺算长度。
4. **交叉验证**：用 OpenStreetMap 的校园道路数据（只下载了公开地图数据，没发送任何个人信息）再做一遍仿射对齐（残差 1.5 – 7.5 米），各边长度都比总平面图长 2 – 3%；另外沿 OSM 道路折线直接量了 5 段（明达路两段、梁希路两段、郑凝路），和总平面图结果差 −2% ~ +4%。
5. **显示**：四舍五入到 10 米，除上面两条微调外都没动。
6. **核对图**：`开发\核对图\核对-体育场地分布图.jpg`、`开发\核对图\核对-总平面图.jpg` 把顶点、道路折线、长度叠在原图上，可以肉眼检查有没有画歪。完整数字在 `开发\测量结果.txt`。

步行时间按 80 米/分钟、向上取整（280 米 → 4 分钟）。

## 迪杰斯特拉过程（默认：生命科学学院 G → 32号教学楼 C）

表里每格是 dist / path（前驱），带 ✓ 的是已锁定；∞ 表示还没路。

| 步骤 | 锁定 | A | B | C（终） | D | E | F | H |
|---|---|---|---|---|---|---|---|---|
| 初始化 | G（起点，0） | ∞ | ∞ | ∞ | 130 / G | ∞ | 120 / G | ∞ |
| 第 1 次 | F（120） | ∞ | ∞ | 300 / F | 130 / G | 250 / F | ✓ 120 / G | 330 / F |
| 第 2 次 | D（130） | ∞ | 200 / D | 300 / F | ✓ 130 / G | 250 / F | ✓ | 330 / F |
| 第 3 次 | B（200） | 370 / B | ✓ 200 / D | **~~300~~ → 280 / B** | ✓ | 250 / F | ✓ | 330 / F |
| 第 4 次（自动） | E（250） | 370 / B | ✓ | 280 / B | ✓ | ✓ 250 / F | ✓ | 330 / F |
| 第 5 次（自动） | C（280）终点，停 | 370 / B | ✓ | ✓ 280 / B | ✓ | ✓ | ✓ | 330 / F |

最短路径：生命科学学院 → D → B → 32号教学楼，**280 米**（第二短 300 米，经 F）。

## 核对和测试结果

- `开发\核对结果.txt`（verify.py）：**323 项全部通过**。包括：显示权值都是 10 的倍数、和实测差 ≤ 10%、只有上面两条偏离取整；heapq Dijkstra 与 Bellman-Ford 全源一致；枚举简单路径，6 栋楼 30 个有序对的最短路都唯一；页面导出的每一步 dist / path / 锁定状态逐格和 Python 算的对上、锁定顺序没有同距离、"改小"记录一致、终点锁定就停；第 1 步蓝线 = 迪杰斯特拉结果 = 枚举出的唯一最短路，而且蓝线和揭晓时的橙线是同一条折线；"全程 xxx 米" = dist[终点]；步行分钟数正确。默认这对还检查了：锁定 ≤ 10 次（5 次）、至少一次改小（1 次，在第 3 次锁定）、结束时 dist 互不相同、第二短在 15% 以内（300 vs 280）。
- `开发\交互测试结果.txt`（test_interact.py，本机 Edge，1920×1080 / 1366×768 / 1280×1024 三种窗口）：**97 项全部通过**。点楼名换终点 / 起点（含点击坐标换算）、模式按钮和 S 键、R、点击 / 方向键 / PageDown·PageUp / 右键 / 按钮 / 数字键 / Enter 翻页、前 3 下一按一步、第 4 下自动播放、暂停、暂停时右键退回、继续、终点锁定后自动揭晓、换成 和润楼 → 数字图书馆 后后面几步跟着换、屏蔽右键菜单、没有脚本错误。
- 截图（`开发\截图\`）：`full-*`（1920×1080）、`w1366-*`、`w1280-*` 每步一张，`debug-*` 是 `?debug=proj` 下检查画布数字和放倒的地图是否对齐；`交互-*` 是交互测试里的截图。1920×1080 的大部分步骤和另外两种窗口下的关键几张看过，没发现重叠、出框。
- 备份视频抽帧看过：导入、导航、第 1 次锁定、第 3 次锁定（300 → 280）、揭晓都正常。

## 每一步老师可以说的（提示，不是台词）

1. **导入（手绘图）**："从生科院下课，要赶去 32 号楼，怎么走最近？大家平时怎么决定？——打开手机导航。"
2. **导航地图**："导航说 280 米、走 4 分钟，走的是图书馆那边，不是沿梁希路、明达路这条看起来更直的路。它是怎么算出来的？"（可以请学生点一栋楼换终点，看路线马上变。）
3. **放倒、路口变顶点**："电脑看不懂地图，它只关心'路口'和'路口之间有多远'。把路口变成点……"
4. **路段变边**："……把路变成线，标上长度。这就是'图'，地图问题变成了图上的最短路径问题。"
5. **初始化**："从起点出发，直接连着的 D 和 F 先记下距离：130、120；别的还到不了，记∞。path 记'从哪个点过来'。"
6. **第 1 次锁定 F**："没确定的里面谁最近？F，120。F 已经不可能有更短的路了，锁定。从 F 出发，E、32 号楼、H 都有路了。"注意 32 号楼此时是 300——"沿着明达路走，300 米。"
7. **第 2 次锁定 D**："现在最近的是 D，130，锁定。从 D 能到 B，200。"
8. **第 3 次锁定 B（停下来讲）**："锁定 B 以后，32 号楼可以从 B 过去：200 + 80 = 280，比原来的 300 小，改！这就是迪杰斯特拉的关键：找到更近的路就更新。"
9. **第 4 下自动播放**："后面都一样：每次挑最近的锁定。E 250 比 280 小，也要先锁……32 号楼 280，锁定，终点确定了，就可以停。H、A 根本不用再看。"
10. **揭晓**："算出来的路径，和刚才导航的蓝线完全重合——导航给你的路线，就是最短路径。顺着 path 往回读：32 号楼 ← B ← D ← 生科院。"

## 已知限制 / 说明

- 校园地图是示意性的：两张图对齐残差约 1 – 13 米，单条边误差估计在 ±5 米左右；OSM 系统性地长 2 – 3%。显示值是"取整 + 两处小于 10% 的微调"，不是精确测量值，课堂上说"大约"即可。
- 道路名来自 OpenStreetMap 和总平面图，个别小路（如"工学院南侧路""图书馆北路"）是为了说明方便起的描述性名字，不一定是学校的正式路名。
- 只放了 8 个顶点（课堂可读性优先），德清湖湖边步道、明达路以东等没放进图。
- 步行速度按 80 米/分钟，只是常见的估计。
- 只在本机 Edge 上测过（Chrome 内核相同，应该也行）；没在投影仪上实测，第一次上课前建议用教室电脑打开按一遍。
- 手绘地图来自"湖师青年1958"（微信公众号），页面右上角已注明出处，比赛使用请保留。
