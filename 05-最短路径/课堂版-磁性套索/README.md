以后这节课的 G6 迪杰斯特拉分步 HTML 也放在这个目录。

## 怎么用

打开后按 **F** 全屏（或者按 F11）。页面按 1920×1080 设计，别的分辨率会等比缩放。
键盘、鼠标、翻页笔都能翻页；右下角有一组不显眼的"‹ / 下一步 ›"按钮。

**第 1 步 · 抠图**
- 在猫的轮廓上**点一下**作为起点；移动鼠标，从上一个点到鼠标的线会**实时贴着边缘走**；再点一下把这一段固定下来。
- 回到起点附近**点一下**（起点周围会出现一个跳动的圆圈）或者**双击**，闭合轮廓，背景淡掉，猫被"抠"出来。
- 闭合之后，**左键点画面任意位置 = 下一步**。闭合之前左键用来落点，要前进就点右下角的"**下一步 ›**"按钮或按 →（点按钮不会落点）。
- **右键 / Backspace**：撤销上一个点。**R**：全部重来。
- 来不及点？什么都不点直接按 →（或点"下一步 ›"），页面会自己沿着预设的点描一遍（再按一次立刻描完）。点了几下但没闭合时按 →，会把最后一个点和起点连起来闭合。

**第 2 步 · 放大**（每前进一次）
1. 镜头拉近到轮廓上自动挑出的一小块 **6×4 像素**，第 1 步那条线在像素格子里走成台阶；
2. 每个像素变成一个圆点（顶点），颜色就是这个像素的颜色；
3. 上下左右相邻的像素连边，标上 1–9 的整数权值：越像边缘（两边明暗差越大）权越小，线也越粗越深。

**第 3 步 · 揭晓**
- 从"起点"出发跑迪杰斯特拉。**前 3 次一按一步**：每次锁定一个距离最小的顶点（变橙色），刚被更新的邻居距离数字会跳一下，方便讲清"每次锁最小的"。
- **第 4 次起自动播放**：每 0.6 秒锁定一个顶点，右下角按钮变成"暂停 ❚❚"；**自动播放中再按一次（键盘、左键、翻页笔都行）= 暂停**，按钮变成"继续 ›"，再按一次继续。暂停时 ← / 右键可以一次退回一步。
- **终点一被锁定就停**（迪杰斯特拉提前结束，剩下没锁定的顶点保持原样），停 1 秒自动进入揭晓：最短路径亮出来，第 1 步那条线沿同一串像素描一遍，大字"这条线 = 最短路径"。
- **Enter**：直接跳到结束（揭晓）。
- 用内嵌的黑猫时，小图要锁定 **13 个顶点**到终点。所以第 3 步一共只要**按 4 下**：3 下手动 + 1 下开始自动播放（约 6 秒跑完，自动揭晓）。

**按键 / 鼠标一览**

| 操作 | 作用 |
|---|---|
| 空格 / → / ↓ / PageDown（翻页笔"下一页"） | 下一步（动画还没放完时，第一下是直接跳到动画结尾）；第 3 步自动播放中 = 暂停 / 继续 |
| ← / ↑ / PageUp（翻页笔"上一页"） | 上一步（第 3 步里是退回一次锁定） |
| 鼠标左键点画面 | 第 1 步闭合前：落点；闭合后及第 2、3 步：下一步（自动播放中 = 暂停 / 继续） |
| 鼠标右键 | 第 1 步：撤销一个点；第 2、3 步：上一步（不会弹出浏览器菜单） |
| 右下角"下一步 ›" / "‹" 按钮 | 下一步 / 上一步（第 1 步只有"下一步 ›"） |
| Enter | 第 3 步直接跳到结束；第 1 步等于"下一步" |
| R | 重来：第 1 步清空轮廓；第 3 步回到刚开始 |
| 1 / 2 / 3 | 直接跳到第几步（2、3 需要轮廓已经闭合） |
| F | 全屏 / 退出全屏 |
| H | 隐藏 / 显示角落里的按键提示（会记住；右下角按钮不隐藏） |

## 原理（给老师备课参考）

照 Mortensen & Barrett 1995 "Intelligent Scissors" 的思路，纯 JavaScript 自己实现（没用 OpenCV）：

- 照片缩到长边 800（800×420）做计算。**每个像素是一个顶点，上下左右相邻的像素连一条无向边**。
- 局部代价 = 0.72 × (1 − 梯度幅值) + 0.28 × (不是 Laplacian 过零点) + 0.25 × (走向和边缘方向不一致)。按"边两端的平均"算，除以总权重，再**量化成 1–9 的整数**。
  - 梯度：先对三个颜色通道做高斯模糊（σ=2），再用 Sobel 算，按 98.5% 分位数归一化。
  - 过零点：只在梯度够强的地方算。
  - 第 1 步和第 3 步用的是**同一份整数边权**。
- 每点一下，就从这个点跑一遍迪杰斯特拉（二叉堆），得到整张图（33.6 万个顶点）的前驱数组，本机约 25 毫秒。鼠标移动时只沿前驱回溯，所以很流畅。点击时会吸附到附近 4 像素内梯度最大的像素。
- 第 2 步自动在闭合的轮廓上挑一块 6×4，条件是：
  - 轮廓从左边进、右边出，且不走最上、最下两行；
  - **这块小图上起点→终点的最短路唯一**；
  - 优先：有拐弯、线上的权小、线外的权大、两边明暗差大、第 3 步要锁定的顶点少（课堂上不拖沓）。
- 为什么第 3 步的最短路径一定和第 1 步那段线一样：
  1. 第 1 步那段线是两个落点之间的最短路。**最短路的任意一截也是最短路**（最优子结构），所以小块里那一截就是起点→终点在整张图上的最短路。
  2. 它整个落在小块里，而小块是整张图的子图，所以它也是小块上的最短路。
  3. 小块上的最短路又是唯一的，所以两者只能逐像素相同。

**和最初需求的一处不同**：需求里写的是 8 邻域（对角乘 √2），这里改成了 **4 邻域**。原因：要让第 3 步的小图和第 1 步真正是同一张图，8 邻域的小图每个格子里都有两条交叉的对角边，6×4 会有 68 个权值挤在一起，投屏看不清；而且对角权乘 √2 后不再是 1–9 的整数。4 邻域下只有 38 条边，权值字号 40 px，清清楚楚。代价是第 1 步的线在像素级上是"台阶"，但在屏幕上（每个计算像素约 2 个屏幕像素、线宽 5 px）看不出来，截图里贴边效果很好。

## 核对与测试

`开发\scripts\verify.py` 用 Python 独立重写（不复用页面里的 JS）来核对页面导出的数据，结果见 `开发\核对结果.txt`。两种轮廓（鼠标点 8 下 / 自动描 13 点）**全部通过**：

- 小图 38 条边都是 1–9 的整数；heapq Dijkstra 与 Bellman-Ford 暴力结果一致。
- 第 3 步 14 个状态 × 24 个顶点，每个显示的距离数字都与独立计算一致：已锁定的 = 真实最短距离，未锁定的 = 已锁定邻居 + 边权的最小值，没有则 ∞。每一步锁定的都是剩下里距离最小的，锁定 13 个顶点后终点被锁定、停止。
- 小图上起点→终点的最短路唯一，等于页面画的路径，也等于第 1 步那段线（同一串 7 个像素，且确实是第 1 步轮廓中连续的一截）。
- 在整张 800×420 图上，A→B 的最短距离 = 第 1 步那段线的代价 = 小图上的 d(终点) = 8；第 1 步每一段轮廓都是两个落点之间的最短路。
- 用 numpy/scipy 独立重算全图 67 万条边的边权：只有 4 条因浮点舍入正好落在 .5 附近而差 1，小图里的边全部一致。

`开发\scripts\test_interact.py` 在 1920×1080、1366×768、1280×1024 三种窗口下做交互回归，75 项全部通过，无脚本报错，结果见 `开发\交互测试结果.txt`。覆盖的操作：

- 第 1 步：点击坐标换算、右键 / Backspace 撤销、双击闭合；闭合前点"下一步 ›"只闭合不落点；
- 翻页：闭合后左键前进、第 2、3 步右键后退、"‹ / 下一步 ›"按钮、翻页笔 PageDown / PageUp、R、数字键；
- 第 3 步：前 3 下一按一步、第 4 下自动播放、播放中点击暂停、暂停时右键退回、再按继续、终点锁定后自动揭晓、Enter 直接到结束；
- 其他：屏蔽右键菜单、自动描、拖入照片。

## 已知限制

- 小块是自动挑的，位置取决于老师当场描的轮廓。用内嵌黑猫时，试过的几种描法（稀疏 5 点到密集 21 点）都落在猫背右上方那一块：背景是浅色木头，猫毛有反光、偏灰，所以小图上是"浅—灰—黑"三层，最短路沿着权为 1 的那一行走。挑不到合适的小块时会提示"换个位置多点几下再试"。
- 边权只有 1–9 九档，等长的路很多，所以小块必须挑"最短路唯一"的地方。猫耳朵那种斜边上等长的台阶太多，挑不中。
- 猫胸口贴着阴影里的木头、背部右上角的毛和背景明暗差小，点得太稀时线会抄近路切进背景一点；在这些地方多点一下就好。
- 按 F 全屏需要浏览器允许；个别情况下不响应就按 F11。
- 只在 Edge（Chromium 129）上测过，Chrome 是同一内核；没测 Firefox。
- 拖进来的照片如果很小（长边不到 800），放大显示会有点糊，计算图也就是原尺寸。
- 备份视频里的鼠标箭头是页面画的（录屏模式 `?record`），没有声音。
