### 2 核心思想（3 步，一按出一句，纯文字、大字）

① 从还没确定的点里，挑**离起点最近**的一个　② 把它**确定下来**（锁定）　③ 再用它去**更新邻居**；第 3 步下面一行"重复这三步，直到所有点都确定"。

老师可以说："整个算法就这一句话。为什么敢把最近的那个直接'定下来'？先留个疑问，第 6 段回答。"

### 3 三样东西（3 步，一按出一行）

| 名字 | 屏幕上的解释 | 例子 |
|---|---|---|
| `dist[v]` | 从起点到 v，目前找到的最短距离 | 例：dist[F] = 120（之后还可能被改小） |
| `path[v]` | 这条路上，v 的前一个点 | 例：path[F] = G（倒着读，就是整条路） |
| `S` | 已经确定（锁定）的点 | 一开始 S = { G }（图上锁定的点涂成橙色） |

老师可以说："dist 是'目前最好的成绩'，随时可能被刷新；path 只记'从哪个点过来'，不记整条路；S 是'已经定死的'。"

**和教材的对应**（叫法和导航演示一致）：

| 这里 | 严蔚敏《数据结构（C 语言版）》清华版 算法 7.15 | 说明 |
|---|---|---|
| `dist[v]` | `D[v]` | 完全一样 |
| `path[v]`（前驱） | `P[v][]`（布尔矩阵：`P[v][w]` 为真表示 w 在 v0 到 v 的当前最短路径上） | 教材记的是"路径上有哪些点"，这里只记"前一个点"，倒推就能还原整条路，信息量相同、更省地方；教材表格里写的 "(v0, v2, v3)" 就是这里倒推出来的那条链 |
| `S` | `final[v]`（为真 ⇔ v ∈ S） | 完全一样 |

如果老师手上是人民邮电第 2 版（严蔚敏、李冬梅、吴伟民），那一版的算法里就叫 `S[i]`、`D[i]`、`Path[i]`，`Path` 也是前驱，和这里一一对应。（算法编号和页码请按老师手上的版本再核一下，我没有书可查。）

### 4 逐轮推进（21 步：初始化 1 步 + 第 1–6 轮各 3 步 + 第 7 轮 2 步）

版式：左上是缩小的图（顶点字母、边长字号都没缩），右上是这一步的大字说明 / 算式，下面是**教材式的历史表**：每轮一列、保留历史，学生可以直接抄进笔记。

- 表的**第 i 列 = 第 i 轮选点之前的状态**（和教材"i = 1, 2, …"的表一样），所以"下一个锁定谁"就是"看最新一列，没确定的格子里谁最小"；第 1 列就是初始化。
- 格子写 `dist path`（比如 `300 F`）；`∞` 表示还到不了；已经确定的点在后面的列里不再写（留空）；path 是起点时写成绿色。
- 被选中的格子画橙框，最下面"锁定"行写出这一轮锁了谁；行首的字母圈锁定后变橙。

### 6 为什么锁定之后不会再变短（7 步）

前 5 步用"第 3 轮刚锁定 B（200）那一刻"的真实状态：S = { G, F, D }（图上浅橙色一块），B 刚变橙，其余候选 C 300、E 250、H 330 标在旁边。

| 步 | 画面（下面的文字一行一行加） | 老师可以说的 |
|---|---|---|
| 1 | 标题"**讨论：锁定之后，dist 还会变小吗？**"（互动点）；"此刻：B 刚被锁定，dist[B] = 200" | **先让学生讨论 1–2 分钟**："会不会以后从别的地方绕过来，比 200 还短？" |
| 2 | 红虚线画出一条"假设的更短路"G → F → C → B；"假设：到 B 还有一条更短的路（< 200）（图上红虚线）" | |
| 3 | S 那一块涂浅橙，标"S（已确定）"；C 加红圈、标"X：300"；"它总要走出 S，第一个出 S 的点记作 X（比如 C）" | "从 G 出发，总得有一步跨出 S。" |
| 4 | G → F → C 变成红实线；"光走到 X，就至少要 dist[C] = 300""B 是没确定的点里最近的：dist[X] ≥ dist[B] = 200" | "光走到 C 就 300 了，已经比 200 长。" |
| 5 | "后面的边长都 ≥ 0 → 整条路 ≥ 200，矛盾！""所以：锁定那一刻，dist 就是最短距离" | |
| 6 | 换成一个 3 个点的小**有向图**：起 → P 2，起 → Q 5，Q → P −4。"有向图反例：迪杰斯特拉第一个锁定 P，dist[P] = 2" | "如果边可以是负的呢？" |
| 7 | 起 → Q → P 变红；"可是 起 → Q → P = 5 + (−4) = 1 < 2，P 锁早了！""所以：迪杰斯特拉要求边权 ≥ 0" | "上一页'后面的边 ≥ 0'这一句不成立了，证明就断了。" |

X 的选法：优先挑和 B 直接相连的候选（默认图里是 C），这样"假设的更短路"整条都画在真实的边上，学生能直接算 120 + 180 + 80 = 380 ≥ 200；没有相连的候选时（换了起点）就挑 dist 最小的候选，后半段画成虚线弧。反例用有向图，是因为无向图里一条负边来回走就是负环，最短路不存在，不适合当反例。

### 8 算法框架和复杂度（3 步）

| 步 | 画面 |
|---|---|
| 1 | 9 行伪代码（大字等宽，用 dist / path / S 的叫法）：初始化 → 重复 n − 1 次：挑 u → 加入 S → 对每个不在 S 里的邻居 v，若 dist[u] + w(u, v) < dist[v] 就改 dist[v]、path[v] |
| 2 | 三行标橙并加注："← 共 n − 1 轮""← 找最小：O(n)""← 更新邻居：O(n)" |
| 3 | 大字"总时间：(n − 1) × O(n) = **O(n²)**"，下面一行灰字"（用小根堆找最小可以更快，课后了解）" |

老师可以说："每一轮都要把没确定的点扫一遍找最小，这是 O(n)；一共 n − 1 轮，所以 O(n²)。用邻接矩阵存图就是这个复杂度。"

### 9 小结（1 步）

五行：单源最短路径 = 一个起点 → 其余所有点；每轮挑没确定里 dist 最小的、锁定、更新邻居；更新规则 dist[u] + w(u, v) < dist[v] 就改、path[v] = u；锁定后不会再变短（前提：边权不能为负）；读路径顺着 path 倒推，时间复杂度 O(n²)。最后一行灰字"拓展：PS 里的'磁性套索'抠图，用的也是它"，接下一个环节。

## 对讲法的调整和理由

任务里给的 9 步都做了，下面是细节上的取舍：

1. **历史表用教材的"第 i 列 = 选点前的状态"**，而不是"每轮更新后加一列"。这样"下一个锁定谁"有明确的依据（看最新一列找最小），和教材的表一一对应，学生抄笔记不会和书对不上。
2. **每轮 3 下：问 → 锁 → 更新**。"问"单独一步，留给老师提问；"更新"里算式一条一条出、算完新的一列才出现，先算后记。没有邻居要更新的轮（E、H）也单独一步"没有要更新的，下一列照抄"，保持节奏，也让学生看到"锁了不一定改"。第 7 轮锁完直接结束，不出空的"更新"。
3. **算式写成两行**：`C：dist[B] + 80 = 280 < 300` / `→ 改为 280，path = B`。一行写下大约 1100 像素宽，44px 字放不进右上角，所以拆两行；dist[B] 的值（200）就在同一页的标题"用 B（200）更新邻居"里，没有在算式里再展开成 200 + 80。
4. **图在第 4 段缩到 0.6 倍、放左上角，字不缩**（顶点字母 36px、边长 36px、表格和算式 44px）。8 个顶点 × 7 列的表在 44px 下宽 1170 像素、高 520 像素，只能放在下半屏；把图缩小比"图 / 表分两屏来回切"更好，学生能同时看到图上哪条边在更新、表里哪一格在变。
5. **第 1 段多一步"导航那一帧"**：第 1 步和导航演示第 2 步结束时完全一样（含楼名和起 / 终），按一下才变抽象，课堂上从导入切过来不会"跳"。
6. **第 5 段加了"你来读：E 怎么走？"**，多一个学生互动点。
7. **第 6 段加了"讨论"标题**作为讨论话题（评委看重小班互动）；X 优先选和 B 直接相连的点，让"假设的更短路"全画在真实的边上，数字能直接算；负权反例用最小的 3 点有向图。
8. **第 7 段做了倒计时、点顶点换题、Enter 完整算一遍**，换起点后第 4–7 段全部跟着变（交互测试和核对脚本都测了 8 个起点）。
9. **同距离的规则**：页面约定"一样近时按字母先锁"，出现时会在"锁"那一步写"X、Y 一样近，挑哪个都对，这里按字母先锁 X"。不过这张图**换 8 个起点都不会出现同距离**（核对脚本检查过），这条规则实际上用不上，页面上也就不会出现这句话。
10. 小结最后加了一行引到"磁性套索"，因为这节课的下一个环节就是它。

## 已知限制 / 需要老师或用户定的

- **表格格子写的是"前驱"不是完整路径**：教材的表写 "60 (v0, v4, v3)"，这里写 "60 v3" 一样的意思（倒推得到）。如果老师要求和书上一模一样写完整路径，7 列在 44px 字下放不下，需要换成"只显示最新 2–3 列"之类的做法——请老师定。
